# Authentication Local HTTPS

Browser Authentication tests must use `https://app.localhost:3443`; plain HTTP cannot exercise the approved Secure refresh cookie. Install `mkcert`, trust its local CA, and issue a development-only certificate for `app.localhost`. The later M1 reverse-proxy Compose profile terminates TLS on port 3443, proxies `/` to web port 3000, and proxies `/api/v1` to API port 8080. Certificate files remain ignored and owner-readable only.

The browser/E2E base URL uses the HTTPS proxy. Its direct API peer must be listed explicitly in `AUTH_TRUSTED_HTTPS_PROXY_CIDRS`; the proxy strips client-provided `X-Forwarded-Proto` and forwards exactly one `X-Forwarded-Proto: https`. CI uses an isolated generated certificate accepted only by its test browser. Do not set `Secure=false`, add a cookie Domain, copy client-IP CIDRs into the HTTPS-proxy setting implicitly, or use the direct API port for browser-auth validation. If certificate trust fails, verify the local CA installation, hostname, proxy route, configured trusted HTTPS proxy CIDR, and browser profile before testing Authentication.
