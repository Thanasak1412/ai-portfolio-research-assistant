## Proposed failure and acknowledgement procedure

The following is design text for S4-3 through S4-6 review, not an implemented pipeline:

1. Preserve a stable safe incident identity and unresolved status. Correlate each attempted notification and outcome without copying financial or provider data.
2. Treat submission, provider acceptance, recipient receipt, Gmail forwarding and human acknowledgement as separate evidence. Only an actual operator action with actor/time acknowledges the incident.
3. Record rejected, uncertain, deferred or failed delivery separately. Apply only approved transport retry budgets; their absence blocks implementation of this route. Preserve failure evidence for a review path that remains usable when email fails.
4. The sole operator reviews unresolved incidents during the accepted next applicable coverage window: weekdays 20:00–23:00 Asia/Bangkok; weekends/public holidays all-day best effort. Planned absence needs a documented safety assessment; unplanned absence implies no backup. There is no 24/7 monitoring or response SLA.
5. Keep unattended/undelivered incidents unresolved, with safe occurrence and acknowledgement history. Do not infer an alternative inbox, responder, automatic resolution or repair authority.
6. Apply only separately approved, implemented and tested safety mechanisms. No email state or Issue state authorizes outbox ACK, replay, destructive repair or receiver reactivation. ADR-023's absent-receiver invariant continues to apply.
